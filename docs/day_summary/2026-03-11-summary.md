## Major Outcomes

### 1. Batch execution was improved

The earlier batch flows were identified as a reliability problem because they processed sites sequentially in long-running request loops, which increased the chance of:

- `502`
- timeouts
- runtime instability

The batch execution work introduced bounded async concurrency so batch operations no longer depend on naive per-site synchronous loops.

This was applied to the batch operations in the cloner flow, including:

- batch account access
- batch site delete
- batch site provision

Key direction:

- use bounded concurrency instead of unbounded parallelism
- isolate per-site failures
- reduce long request pressure
- move toward more durable batch orchestration

This remains the batch-side foundation for later job-style improvements.

### 2. Individual Configuration now has a dedicated backend model

The site-level individual configuration flow was moved away from raw Aruba proxy dependence and toward a dedicated backend-owned model.

This model now supports:

- normalized individual network list
- wireless overview update wiring
- network delete wiring
- wireless IP Assignment wiring
- wireless Network Assignment wiring

Why this matters:

- frontend no longer has to shape raw Aruba payloads directly
- read/update behavior is more stable and easier to extend
- later sections can follow the same pattern instead of inventing one-off frontend logic

### 3. Site vs zone configuration responsibilities are now clearer

The intended architecture now is:

- zone/global configuration:
  - batch tools
- site detail configuration:
  - individual section-based configuration

This is the correct separation going forward.

- opening it routes to `Overview`
- the parent is never highlighted

### Wireless Overview

Implemented end-to-end:

- frontend overview editor
- backend payload merge
- Aruba update path:
  - `PUT /api/sites/{site_id}/networksSummary/{ssid_id}`

Current overview support:

- network name
- enabled
- hidden network
- security mode
- PSK password

### Network Delete

Implemented delete wiring for both network types:

- wireless delete:
  - Aruba `DELETE /api/sites/{site_id}/networksSummary/{ssid_id}`
- wired delete:
  - Aruba `DELETE /api/sites/{site_id}/wiredNetworks/{vlan_id}`

Frontend behavior now:

- confirm before delete
- remove deleted item from local state
- choose next available network
- show empty state if none remain

### IP Assignment

Implemented the first working save path for wireless IP Assignment.

Supported and built today:

- `Same as a Local Network (default)`
  - wired network selection
  - backend updates `wiredNetworkId`
- frontend UI for:
  - `Specific to This Network`
  - DNS Resolution
  - automatic vs static DNS

Validation implemented:

- frontend IPv4 validation for DNS input
- backend deterministic validation for:
  - IPv4 format
  - subnet mask
  - mode-aware required fields

Important correction:

- the earlier pragmatic reachability check was removed
- backend now does deterministic validation only

### Network Assignment

Implemented wireless Network Assignment save flow for radio fields:

- `isAvailableOn24GHzRadioBand`
- `isAvailableOn5GHzRadioBand`
- `isAvailableOn6GHzRadioBand`
- `isLegacy80211bRatesEnabled`

Also implemented:

- `Extended 2.4 GHz range`
- 2.4 GHz dependency:
  - turning off 2.4 GHz hides the radio-options block
  - turning off 2.4 GHz forces extended 2.4 GHz range off

Not implemented yet:

- access point assignment

That panel remains placeholder-only by design.
